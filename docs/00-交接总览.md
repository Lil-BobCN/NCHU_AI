# 交接总览

## 项目定位

本项目是面向学校/单位文档知识库的 RAG 智能问答系统。系统支持管理员上传 PDF、Word、Excel、Markdown、TXT、图片、压缩包等资料，后台完成解析、切片、向量化和索引入库，前端提供文档管理、知识库管理、问答、检索调试、QA 对、评估和反馈能力。

当前交付版本是 Python RAG 独立服务，技术栈为 FastAPI + Vue + PostgreSQL/pgvector + Redis + MinIO，模型侧使用 DeepSeek 问答模型和 DashScope 兼容接口的 embedding/rerank 能力。

## 交接风险提示

1. `.env.example` 只保留占位符，正式部署必须更换真实密钥和强密码。
2. `backend/Dockerfile` 构建时会预加载 PaddleOCR 相关模型，首次构建时间较长，且需要网络或镜像缓存。
3. embedding 维度默认是 `1024`，数据库表 `chunk_embeddings.embedding` 和 `qa_pair_embeddings.embedding` 使用 `vector(1024)`，更换 embedding 模型时必须同步迁移表结构。
4. 后台 worker 是文档处理的关键进程，只启动 API 不启动 worker 时，上传后的文档任务会停留在队列中。
5. Redis 保存任务队列、进度和缓存，Redis 数据丢失可能导致未执行任务需要重新触发，但核心业务数据以 PostgreSQL 和 MinIO 为准。
6. MinIO 的公开访问地址由 `MINIO_PUBLIC_BASE_URL` 决定，生产环境必须配置为前端可访问的域名或反向代理地址。
7. 旧 Office 转换依赖 LibreOffice，容器内已安装，非容器部署时需要额外安装。
8. OCR 依赖 PaddleOCR/PaddlePaddle，Windows 本地环境可能安装较慢，建议优先使用 Docker 或 Linux 服务器部署。

## 建议交接顺序

1. 先按部署文档在新环境跑通健康检查。
2. 初始化管理员并登录前端。
3. 上传 1 个小 PDF 或 TXT，确认文档状态能走到 `indexed`。
4. 在检索调试页查询文档关键词，确认召回和引用来源正常。
5. 在聊天页提问，确认 SSE 流式回答、引用和推荐追问正常。
6. 导入真实业务资料前，确认 `.env`、MinIO 公开地址和数据库备份策略。
