# 交接总览

## 一、项目定位

项目名称：Java Internal RAG Service

交付目录：`D:\job_code\其他项目\南航项目\java_rag`

本项目是供 Java 后台调用的 Python RAG 内部服务，主要负责文档解析、切片、向量化、召回、重排、问答生成、引用来源、问答日志、反馈和评测等能力。

系统边界：

```text
前端 -> Java 后台 -> Python RAG internal API
```

Java 后台负责用户登录、Sa-Token 鉴权、用户/部门/角色、业务文档记录、业务会话入口和权限范围计算。

Python RAG 服务负责验证 Java 传入的 Sa-Token JWT，根据 Java 传入的访问范围过滤可检索文档，并完成 RAG 检索与回答。

## 五、接手优先级

建议接手时按下面顺序确认：

1. 能否启动服务：检查 `.env`、数据库、Redis、MinIO、模型 API Key。
2. Java 鉴权是否打通：确认 `Authorization: Bearer <Sa-Token JWT>` 能通过 `/internal/rag/health`。
3. 文档入库是否正常：Java 上传文件后调用 `/internal/rag/documents/process`，后台 worker 能把文档处理到 `indexed`。
4. 问答是否可用：调用 `/internal/rag/chat` 或 `/internal/rag/chat/stream`，确认能返回答案、引用和消息 ID。
5. 权限过滤是否正确：使用不同部门、用户、知识库范围测试检索结果。
6. 批量任务是否可追踪：调用批量重解析/重切片后，用 `batch_id` 查询 `/internal/rag/jobs`。
7. 反馈闭环是否可用：提交回答反馈，确认会话消息和 `retrieval_logs.answer_quality` 同步更新。
8. 日志和问题追踪是否可用：查看 `retrieval_logs`、`document_jobs`、服务日志。
