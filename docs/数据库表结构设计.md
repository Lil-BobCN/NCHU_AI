# 学校 RAG 智能问答系统 - 数据库表结构设计

> 版本：v1.0  
> 范围：一期 MVP  
> 数据库：PostgreSQL + pgvector  
> 缓存：Redis  
> 文件存储：MinIO  

---

## 1. 设计原则

| 原则 | 说明 |
|------|------|
| PostgreSQL 为主库 | 业务数据、对话数据、文档元数据、切片、QA、检索日志、评测数据都存 PostgreSQL |
| pgvector 做向量检索 | 一期不引入 Milvus，chunk embedding 直接写入 PostgreSQL |
| MinIO 保存文件 | 原始文件、解析产物、预览文件进入 MinIO，数据库只保存 object key 和 URL |
| Redis 只做短期数据 | 任务进度、热点缓存、短期会话缓存、限流计数进入 Redis，不作为长期数据源 |
| 全链路可追溯 | 每次问答记录召回、重排、引用、来源 URL、推荐追问 |

---

## 2. PostgreSQL 扩展

```sql
CREATE EXTENSION IF NOT EXISTS vector;
CREATE EXTENSION IF NOT EXISTS pg_trgm;
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";
```

说明：
- `vector`：存储 embedding。
- `pg_trgm`：支持模糊关键词匹配。
- `uuid-ossp`：生成 UUID。

### 4.6 chunk_embeddings

切片向量表。

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|

| document_id | uuid | fk documents.id | 文档 ID |
| embedding | vector(1024) | not null | 向量。维度按实际 `text-embedding-v4` 返回值确认 |
| embedding_model | varchar(128) | not null | 向量模型名称 |
| embedding_provider | varchar(64) | not null | 模型供应商 |

| created_at | timestamptz | not null | 创建时间 |
| updated_at | timestamptz | not null | 更新时间 |

建议索引：

```sql
CREATE UNIQUE INDEX idx_chunk_embeddings_chunk_id ON chunk_embeddings(chunk_id);
CREATE INDEX idx_chunk_embeddings_document_id ON chunk_embeddings(document_id);
CREATE INDEX idx_chunk_embeddings_content_hash ON chunk_embeddings(content_hash);
CREATE INDEX idx_chunk_embeddings_vector_hnsw
ON chunk_embeddings USING hnsw (embedding vector_cosine_ops);
```

注意：
- `vector(1024)` 是初始建议值，正式开发时需要通过一次 embedding API 调用确认维度。
- 如果实际维度不同，需要同步修改表结构和索引。

## 5. Redis Key 设计

| Key | 类型 | TTL | 说明 |
|-----|------|-----|------|
| `job:{job_id}:progress` | string/json | 24h | 任务进度 |
| `document:{document_id}:status` | string/json | 24h | 文档状态 |
| `conversation:{conversation_id}:context` | string/json | 30min | 短期会话上下文 |
| `rag:query:{query_hash}` | string/json | 10min | 热点问题检索缓存 |
| `qa:hot:{query_hash}` | string/json | 1h | 热点 QA 结果 |
| `rate:{client_id}` | counter | 1min | 简单限流 |

Redis 不作为最终数据来源。Redis 丢失后，系统应能从 PostgreSQL 恢复核心状态。

## 6. MinIO Bucket 和对象路径

### 6.1 Bucket

| Bucket | 用途 |
|--------|------|
| `rag-documents` | 原始上传文件 |
| `rag-parsed` | 解析后的 Markdown、文本、中间产物 |
| `rag-preview` | 可预览文件 |

### 6.2 Object Key

```text
documents/{yyyy}/{mm}/{document_id}/{original_file_name}
parsed/{yyyy}/{mm}/{document_id}/content.md
parsed/{yyyy}/{mm}/{document_id}/content.txt
preview/{yyyy}/{mm}/{document_id}/preview.pdf
```

### 6.3 URL 策略

| 字段 | 说明 |
|------|------|
| source_url | 文档外部来源地址，优先展示 |
| preview_url | 系统预览地址，用于回答来源跳转 |
| download_url | 系统下载地址，用于下载原始文件 |

一期使用公网 URL，但建议保留签名 URL 或后端鉴权下载能力。

## 7. RAG 引用数据结构

回答末尾展示的引用建议使用以下结构存入 `citations`：

```json
[
  {
    "document_id": "uuid",
    "document_title": "合同文件.pdf",
    "chunk_id": "uuid",
    "page_start": 3,
    "page_end": 4,
    "section_path": "第三条 服务内容",
    "url": "https://example.com/preview/xxx",
    "source_type": "document"
  }
]
```

前端展示格式：

```text
参考来源：
1. 合同文件.pdf，第 3-4 页，第三条 服务内容
   https://example.com/preview/xxx
```

## 8. 推荐追问数据结构

```json
[
  {
    "question": "这个项目的付款节点有哪些？",
    "reason": "基于当前合同的付款条款推荐",
    "source_document_ids": ["uuid"]
  },
  {
    "question": "合同中对验收时间有什么要求？",
    "reason": "当前回答涉及交付和验收",
    "source_document_ids": ["uuid"]
  }
]
```

规则：
- 每次最多 3 个。
- 无依据时可以少于 3 个。
- 不推荐知识库中明显没有依据的问题。
- 点击推荐问题后，作为下一轮用户问题进入对话。

## 9. 需要开发时确认的点

| 项 | 当前建议 |
|----|----------|
| embedding 维度 | 先通过 `text-embedding-v4` 实测确认，再固定表结构 |
| MinIO URL | 一期公网 URL，后续可改签名 URL |
| 管理员初始密码 | 通过环境变量初始化，不写死在代码 |
| 数据删除 | 一期逻辑删除为主，文件可同步删除或标记删除 |
