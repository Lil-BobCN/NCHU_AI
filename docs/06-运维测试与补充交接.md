# 运维测试与补充交接

## 1. 日常运维检查

| 检查项 | 命令或方式 | 正常结果 |
| --- | --- | --- |
| 容器状态 | `docker compose -f deploy/docker-compose.yml ps` | 服务均为 running/healthy |
| API 健康 | `curl http://127.0.0.1:8010/api/v1/health` | api/postgres/redis/minio 为 ok |
| 后端日志 | `docker compose -f deploy/docker-compose.yml logs -f backend` | 无持续异常 |
| worker 日志 | `docker compose -f deploy/docker-compose.yml logs -f worker` | 上传任务能执行完成 |
| PostgreSQL | `docker exec rag_postgres pg_isready -U rag` | accepting connections |
| Redis | `docker exec rag_redis redis-cli ping` | PONG |
| MinIO | 打开 Console 或检查 API | bucket 可访问 |

### 2.3 业务验收

建议准备一份业务验收问题集：

| 类型 | 示例 |
| --- | --- |
| 精确事实 | 文档中的金额、日期、联系人、条款编号 |
| 跨段总结 | 某项政策的申请条件和流程 |
| 表格查询 | 某行某列、费用明细、课程安排 |
| 无依据问题 | 知识库没有的信息，应明确无法从资料确认 |
| 多轮追问 | 上一轮问题中的对象继续追问 |

验收标准建议：

1. 回答必须基于已上传资料。
2. 关键事实必须有引用来源。
3. 无依据问题不能编造。
4. 引用文件名和页码/章节尽量正确。
5. 检索命中率稳定后再批量导入真实资料。

## 3. 常见故障处理

### 3.1 文档上传成功但不处理

排查：

1. worker 是否启动。
2. Redis 是否可连。
3. `document_jobs` 是否有新任务。
4. worker 日志是否有模型 key、MinIO、解析异常。

处理：

1. 启动或重启 worker。
2. 在文档页手动重解析。
3. 检查 `.env` 中 `REDIS_URL`。

### 3.2 文档处理失败

排查：

1. 文档详情中的 `error_message`。
2. `/api/v1/documents/{id}/jobs`。
3. worker 日志。
4. 文件类型是否支持。
5. 是否超过大小限制或解析字符预算。

处理：

1. 对旧 `.doc/.xls` 先执行转换。
2. 对压缩包先确认内部文件类型。
3. 扫描件 PDF 需要启用 OCR。
4. 超大表格需要调整表格切片和预算配置。

### 3.3 问答没有引用或回答空

排查：

1. 文档状态是否为 `indexed`。
2. 检索调试是否能命中相关 chunk。
3. embedding/rerank key 是否可用。
4. `SIMILARITY_THRESHOLD` 或 `RERANK_THRESHOLD` 是否过高。
5. `MINIO_PUBLIC_BASE_URL` 是否浏览器可访问。

处理：

1. 重向量化文档。
2. 降低阈值后验证。
3. 检查模型调用日志。
4. 在检索日志中查看召回和重排结果。

### 3.4 前端接口 502 或超时

排查：

1. 后端容器是否运行。
2. Nginx 代理配置是否指向 `backend:8000`。
3. 后端日志是否有异常。
4. 模型请求是否超时。

处理：

1. 重启 backend 和 frontend。
2. 调大 `MODEL_REQUEST_TIMEOUT_SECONDS`。
3. 确认服务器能访问模型服务地址。

### 3.5 MinIO 文件不能预览

排查：

1. `MINIO_PUBLIC_BASE_URL` 是否是浏览器可访问地址。
2. 前端 Nginx 是否代理 `/rag-documents/`、`/rag-parsed/`、`/rag-preview/`。
3. bucket 和 object key 是否存在。

处理：

1. 修正公开地址。
2. 重启 backend，使新配置生效。
3. 对旧文档可重新生成访问 URL 或重新上传。

## 4. 备份策略

建议至少备份：

| 数据 | 频率 | 说明 |
| --- | --- | --- |
| PostgreSQL | 每日 | 业务数据、向量、会话、日志 |
| MinIO | 每日或实时同步 | 原始文档、解析结果 |
| `.env` | 变更后备份 | 密钥和连接配置，需安全保存 |
| 镜像版本 | 每次发布 | 便于回滚 |

Redis 主要用于队列和缓存，不建议作为核心恢复对象；如果有大量进行中任务，发布前应暂停上传或等待任务完成。
