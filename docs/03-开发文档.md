# 开发文档

## 1. 开发环境准备

推荐 Windows 本地开发流程：

```powershell
python -m venv .venv311
.\.venv311\Scripts\python.exe -m pip install -U pip
.\.venv311\Scripts\python.exe -m pip install -r backend\requirements.txt
npm --prefix frontend install
Copy-Item .env.example .env
```

启动基础依赖：

```powershell
docker compose -f deploy/docker-compose.yml up -d postgres redis minio
```

数据库迁移：

```powershell
$env:PYTHONPATH='backend'
.\.venv311\Scripts\python.exe -m alembic -c backend\alembic.ini upgrade head
.\.venv311\Scripts\python.exe -m app.init_admin
```

启动后端：

```powershell
.\scripts\run-backend-dev.cmd
```

启动 worker：

```powershell
$env:PYTHONPATH='backend'
.\.venv311\Scripts\python.exe -m app.workers.document_worker
```

启动前端：

```powershell
.\scripts\run-frontend-dev.cmd
```

## 3. 后端分层约定

| 层 | 职责 |
| --- | --- |
| API 层 | 参数校验、鉴权、HTTP 状态、调用 service |
| Service 层 | 业务逻辑、文档流水线、模型调用、检索、缓存 |
| DB 层 | ORM 模型、session、SQL 执行 |
| Worker 层 | 从 Redis 取任务并分发给 service |

新增功能时建议遵循：

1. 路由只做输入输出，不写复杂业务。
2. 数据库写入尽量放到 service。
3. 任务型操作通过 `TaskQueueService` 入队，由 worker 执行。
4. 用户可感知的耗时操作要写入 `document_jobs` 或对应日志表。
5. 新增表结构必须添加 Alembic 迁移，并同步更新 `backend/sql/001_init.sql`。

## 5. API 开发规范

后端成功响应统一使用：

```json
{
  "code": 0,
  "message": "ok",
  "data": {}
}
```

错误响应主要来自 FastAPI `HTTPException`：

```json
{
  "detail": "错误说明"
}
```

鉴权方式：

```http
Authorization: Bearer <access_token>
```

新增 API 时建议：

1. 路径放在 `/api/v1` 下。
2. 需要登录的接口添加 `Depends(get_current_admin)`。
3. 分页参数统一使用 `page` 和 `page_size`。
4. 可批量处理的接口限制最大数量，当前文档批量接口限制 200 个。
5. 对外返回不要暴露内部异常堆栈。

## 6. 数据库开发规范

数据库采用 PostgreSQL + pgvector。新增表或字段时需要同步：

1. `backend/app/db/models.py`
2. `backend/alembic/versions/*.py`
3. `backend/sql/001_init.sql`
4. `docs/05-接口与数据字典.md`

迁移命令：

```powershell
$env:PYTHONPATH='backend'
.\.venv311\Scripts\python.exe -m alembic -c backend\alembic.ini revision -m "change description"
.\.venv311\Scripts\python.exe -m alembic -c backend\alembic.ini upgrade head
```

注意事项：

1. embedding 维度变更会影响 `vector(1024)` 字段。
2. 大表索引新增要考虑生产执行时间。
3. 软删除数据要确认是否同步清理 MinIO 对象和向量数据。
4. `documents.knowledge_base` 变更后要更新知识库版本。

## 7. 文档处理开发点

文档流水线入口：

| 方法 | 说明 |
| --- | --- |
| `run_full_pipeline_from_storage` | 从 MinIO 读取原文档并执行完整解析、切片、向量化 |
| `run_chunk_and_embed` | 基于已有解析结果重新切片并向量化 |
| `run_embed_only` | 清理并重新生成向量 |
| `run_convert_office` | 旧 Office 转换 |
| `run_extract_archive` | 压缩包解压导入 |

如果要支持新文件类型：

1. 在 `supported_file` 中加入扩展名。
2. 在 `ParseService` 中实现解析逻辑。
3. 增加解析质量判断。
4. 增加单元测试和样本文档验证。
5. 更新前端上传提示和交接文档。

## 8. RAG 开发点

关键服务：

| 服务 | 职责 |
| --- | --- |
| `ModelService` | 问答模型和 embedding 客户端 |
| `RerankService` | rerank 调用和关闭客户端 |
| `RetrievalService` | 多路召回、融合、重排、引用 |
| `ChatService` | 会话、流式回答、消息保存 |
| `QaGenerationService` | 从文档生成 QA 对 |
| `QaEmbeddingService` | QA 对向量同步 |

修改检索策略时需要同步验证：

1. 检索调试接口结果。
2. 聊天回答引用是否正确。
3. `retrieval_logs` 中 trace 是否可读。
4. 评估样本 top3/top5 是否下降。
5. Redis 缓存 key 是否需要失效。

## 10. 常见开发问题

| 问题 | 排查方向 |
| --- | --- |
| 上传后一直不处理 | 确认 worker 是否启动、Redis 是否可连 |
| 文档状态 failed | 查看 `document_jobs.error_message` 和 worker 日志 |
| 没有引用来源 | 检查文档是否 indexed、检索是否命中、MinIO 公网地址是否正确 |
| 前端请求 401 | token 过期或 `.env` 的 JWT 密钥变更 |
| SSE 没有流式输出 | 检查代理是否关闭 buffering，Nginx 已配置 `proxy_buffering off` |
| OCR 构建慢 | PaddleOCR 首次下载模型慢，建议构建镜像缓存 |
| 旧 Office 不能转换 | 检查 LibreOffice 是否安装 |
