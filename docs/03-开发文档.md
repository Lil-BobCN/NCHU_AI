# 开发文档

## 一、开发环境

建议环境：

- Python 3.11。
- PostgreSQL 16 + pgvector。
- Redis 7。
- MinIO。
- Docker Desktop 或服务器 Docker。

创建虚拟环境：

```powershell
cd D:\job_code\其他项目\南航项目\java_rag\backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

如果本机安装 PaddleOCR 或 PaddlePaddle 困难，建议使用 Docker 环境开发和测试。

只做接口契约、服务逻辑和轻量冒烟时，可以临时安装：

```powershell
pip install -r requirements-lite.txt pytest ruff
```

轻量依赖不包含 PaddleOCR/PaddlePaddle，不能替代完整文档 OCR 端到端验收。

## 二、本地直接启动

准备根目录 `.env` 后，启动 API：

```powershell
cd D:\job_code\其他项目\南航项目\java_rag\backend
$env:PYTHONPATH="."
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

启动 worker：

```powershell
cd D:\job_code\其他项目\南航项目\java_rag\backend
$env:PYTHONPATH="."
python -m app.workers.document_worker
```

API 和 worker 必须连接同一个 PostgreSQL、Redis、MinIO。

## 四、接口开发规范

普通管理接口放在 `backend/app/api/v1/`。

Java 后台专用接口集中在：

```text
backend/app/api/v1/internal.py
```

新增 Java 对接接口时建议：

1. 统一挂载在 `/internal/rag` 前缀下。
2. 加入 `dependencies=[Depends(get_current_user_from_sa_token)]` 或在接口参数中显式注入 `CurrentUser`。
3. 响应使用 `ok(data)`，保持 `{code,message,data}` 结构。
4. 不信任前端权限，必须使用 Java 传入的 `access_scope` 做服务端过滤。
5. 请求字段使用 Pydantic Model 定义，给出长度和范围限制。
6. 涉及异步任务时写入 `document_jobs`，并通过 Redis 队列交给 worker。

涉及问答或召回的新 Java 接口，应优先复用 `internal.py` 中的 `_allowed_document_filter`，把权限范围下推到检索 SQL，而不是先在接口层查询大量文档 ID 后传递。

## 五、服务层开发规范

建议保持现有分层：

- API 层只做参数校验、鉴权、响应封装。
- Service 层处理业务逻辑。
- DB Model 只描述表结构。
- 长耗时任务放到 worker。
- 外部 API 调用集中在 `model_service.py`、`rerank_service.py`、`minio_service.py`。

新增文档处理步骤时，优先扩展 `DocumentPipeline`，并维护：

- 文档状态。
- `document_jobs` 进度。
- 失败时 `error_message`。
- 知识库版本 `knowledge_base_versions`。

## 六、数据库开发

新增或修改表结构时：

1. 修改 `backend/app/db/models.py`。
2. 新增 Alembic 迁移文件到 `backend/alembic/versions/`。
3. 如需要全新环境初始化，也同步更新 `backend/sql/001_init.sql`。
4. 本地执行：

```powershell
cd backend
alembic upgrade head
```

涉及向量维度时必须同步：

- `EMBEDDING_DIMENSION`
- `chunk_embeddings.embedding vector(1024)`
- `qa_pair_embeddings.embedding vector(1024)`
- Embedding 模型配置。

## 七、测试

编译检查：

```powershell
python -m compileall -q backend\app backend\tests
```

运行全部测试：

```powershell
cd backend
pytest
```

按模块运行：

```powershell
pytest tests\test_internal_api_contract.py
pytest tests\test_internal_access_scope.py
pytest tests\test_chat_service.py
pytest tests\test_document_api.py
pytest tests\test_knowledge_base_service.py
```

建议新增功能至少补充：

- 接口契约测试。
- 权限过滤测试。
- Service 纯逻辑测试。
- 异常分支测试。

接口冒烟建议基于 `app.openapi()` 枚举全量 path/method，至少确认路由可命中、鉴权和参数校验返回预期状态且没有 500。

本轮冒烟结果：`pytest -q` 为 `99 passed`；`ruff check .` 通过；OpenAPI 全量接口冒烟覆盖 76 个 HTTP 操作，无 500；新增知识库、批量任务、任务列表和反馈接口不带鉴权均命中路由并返回 `401`。

## 八、调试建议

文档处理问题：

- 查 `document_jobs` 的 `status`、`message`、`error_message`。
- 查 worker 日志。
- 查 MinIO 的 bucket 和 object key。
- 查 `document_parse_results` 是否生成。
- 查 `document_chunks` 和 `chunk_embeddings` 是否有数据。

问答问题：

- 查请求传入的 `access_scope`。
- 查 `retrieval_logs` 中的 `raw_query`、`recall_results`、`rerank_results`、`final_context`。
- 查模型 API Key 和限流。
- 查 Redis 缓存是否命中过旧结果。

鉴权问题：

- 解码 Java 传入的 JWT，确认包含 `loginId`、`userId`、`eff`、`timeout`。
- 确认 `SA_TOKEN_JWT_SECRET` 和 Java 端一致。

## 九、编码注意事项

当前代码中历史中文字符串存在乱码现象，交接后建议统一处理：

1. 先建立回归测试，覆盖鉴权、文档入库、问答和权限过滤。
2. 批量修复提示文案和注释编码。
3. 确认所有源文件保存为 UTF-8。
4. 重新执行 `compileall` 和 `pytest`。
