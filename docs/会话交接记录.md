## 1. 项目定位

这是一个给 Java 后台调用的 Python RAG 内部服务项目。

整体链路：

```text
前端 -> Java 后台 -> Python RAG internal API
```

Python 只负责 RAG 能力：

- 文档解析。
- 切片。
- 向量化。
- 检索召回。
- rerank。
- 多轮问答。
- 引用来源。
- RAG 检索日志。

Java 负责：

- 登录鉴权。
- 用户、角色、部门、权限。
- 知识库和文档业务记录。
- 会话和消息落库。
- 反馈和后台管理。
- 每次调用 Python 时传 `user_context` 和 `access_scope`。

核心原则：

```text
Python 不解析 Java Sa-Token。
Python 只校验 X-RAG-Service-Token。
Python 检索前必须先按 Java 传入的权限范围过滤文档。
```

## 9. 远程更新流程

本地打包：

```powershell
tar --exclude='backend/.pytest_cache' `
    --exclude='backend/**/__pycache__' `
    --exclude='backend/**/*.pyc' `
    --exclude='.git' `
    --exclude='.venv' `
    --exclude='.cache' `
    --exclude='rag_java_deploy.tgz' `
    -czf rag_java_deploy.tgz .
```

上传：

```powershell
scp rag_java_deploy.tgz root@47.100.216.222:/tmp/rag_java_deploy.tgz
```

远程更新：

```bash
cd /app/rag-java-internal
cp .env /tmp/rag_java_internal.env

rm -rf /app/rag-java-internal.new
mkdir -p /app/rag-java-internal.new
tar -xzf /tmp/rag_java_deploy.tgz -C /app/rag-java-internal.new
rsync -a --delete /app/rag-java-internal.new/ /app/rag-java-internal/
rm -rf /app/rag-java-internal.new
cp /tmp/rag_java_internal.env /app/rag-java-internal/.env

cd /app/rag-java-internal/backend
docker build -f Dockerfile.reuse -t rag-java-internal-backend:reuse .

cd /app/rag-java-internal
docker compose -p rag-java-internal -f deploy/docker-compose.remote.yml up -d --no-build
python3 deploy/remote_health_check.py
```

更新后清理临时包：

```bash
rm -f /tmp/rag_java_deploy.tgz
```

## 11. 已知需要继续处理的问题

### 11.1 高优先级：任务 ID 契约不一致

当前代码里：

- `POST /internal/rag/documents/process` 返回的是 Redis 队列 task id。
- `GET /internal/rag/jobs/{job_id}` 查询的是 `document_jobs` 表里的 job id。

这可能导致 Java 拿到 `jobs[0].job_id` 后轮询 `/jobs/{job_id}` 查不到任务。

建议下一步修复：

1. 文档 process 接口创建数据库 `DocumentJob`。
2. 返回数据库 `document_jobs.id` 给 Java。
3. Redis task payload 携带该 job id。
4. Worker 执行时更新同一条 job。

这是 Java 联调前最值得先修的点。

### 11.2 Java 状态回写未闭环

文档中提到 Python 回写 Java `knowledge_attach` 状态、写 `knowledge_fragment`。

当前代码现状：

```text
Python 只保存自己的 documents、document_jobs、document_chunks、retrieval_logs。
没有主动回写 Java 业务表。
没有实现 knowledge_fragment 写入。
```

短期可让 Java 轮询 Python 任务接口。

长期建议：

- 增加 Java 回调接口。
- 或 Java 定时同步 Python 任务状态。
- 或明确共库只读/只写规则后写 `knowledge_fragment`。

### 11.3 internal 接口尚未完全覆盖文档

已实现：
