# Java Internal RAG Service 部署运维文档

版本：V1.0  
日期：2026-07-02  
适用项目：`rag_java`

## 0. 2026-07-04 更新说明

- 远程部署改为共用 Java 服务器现有 PostgreSQL，不再由 `docker-compose.remote.yml` 启动独立 `rag_java2_postgres`。
- 远程 `.env` 中的 `DATABASE_URL` 必须指向 Java 现有 PostgreSQL，容器访问宿主机数据库时可使用 `host.docker.internal`。
- 远程部署也改为使用服务器已有 MinIO，不再启动独立 `rag_java2_minio`。
- `/internal/rag/*` 鉴权改为 Java Sa-Token JWT：

```http
Authorization: Bearer <Java Sa-Token JWT>
```

- 远程 `.env` 必须配置 `SA_TOKEN_JWT_SECRET`，值与 Java 端 `sa-token.jwt-secret-key` 一致。
- 旧 `X-RAG-Service-Token` 示例属于历史方案；当前联调以 Sa-Token JWT 为准。

## 1. 部署结论

当前项目已按“远程轻量版”部署到服务器：

```text
服务器 IP：47.100.216.222
部署目录：/app/rag-java-internal
Compose 项目名：rag-java-internal
后端内部服务地址： http://127.0.0.1:18020/internal/rag
公网后端端口：18020
```

当前部署用于 Java 后台调用 Python RAG 内部接口。

重要说明：

- 当前部署没有覆盖服务器上已有的旧 `rag-school` 服务。
- 当前部署使用独立容器名、独立数据卷、独立端口。
- 当前部署为轻量版，`OCR_ENABLED=false`，未安装 PaddleOCR 和完整 OCR 模型。
- 普通 PDF 文本、Word、Excel、Markdown、TXT 等解析能力保留。
- 图片 OCR、扫描件 OCR 后续需要完整镜像和更充足磁盘空间。

## 2. 当前容器清单

| 容器 | 作用 | 端口 |
| --- | --- | --- |
| `rag_java2_backend` | FastAPI RAG 内部服务 | `18020:8000` |
| `rag_java2_worker` | 后台文档处理 worker | 不暴露端口 |
| `rag_java2_redis` | Redis 队列和缓存 | `127.0.0.1:16381:6379` |

PostgreSQL 不再作为本 Compose 的容器启动，Python 通过 `.env` 中的
`DATABASE_URL` 访问 Java 服务器现有数据库。

MinIO 不再作为本 Compose 的容器启动，Python 通过 `.env` 中的
`MINIO_ENDPOINT`、`MINIO_ACCESS_KEY`、`MINIO_SECRET_KEY` 访问服务器已有 MinIO。

Java 如果部署在同一台服务器，建议使用：

```text
http://127.0.0.1:18020/internal/rag
```

Java 如果部署在其他机器，需要在阿里云安全组放行 `18020`。

## 3. 核心接口

所有 `/internal/rag/*` 接口都必须带请求头：

```http
Authorization: Bearer <Java Sa-Token JWT>
X-Request-Id: <trace id，可选但建议传>
```

主要接口：

```text
GET    /internal/rag/health
GET    /internal/rag/documents/{attach_id}
POST   /internal/rag/documents/process
POST   /internal/rag/documents/{attach_id}/reparse
POST   /internal/rag/documents/{attach_id}/rechunk
DELETE /internal/rag/documents/{attach_id}
GET    /internal/rag/jobs/{job_id}
POST   /internal/rag/conversations
GET    /internal/rag/conversations
GET    /internal/rag/conversations/{conversation_id}/messages
PATCH  /internal/rag/conversations/{conversation_id}
DELETE /internal/rag/conversations/{conversation_id}
POST   /internal/rag/chat/stream
POST   /internal/rag/chat
```

Sa-Token JWT 验签配置存放在服务器：

```bash
/app/rag-java-internal/.env
```

不要把 `SA_TOKEN_JWT_SECRET` 放到前端、日志、截图或公开文档中。

## 4. 服务器前置条件

远程服务器需要：

```text

可用磁盘空间建议：
```

## 5. 部署文件说明

当前新增和使用的部署文件：

```text
backend/Dockerfile.reuse
backend/Dockerfile.lite
backend/requirements-lite.txt
deploy/docker-compose.remote.yml
deploy/remote_init_env.py
deploy/remote_health_check.py
```

文件作用：

| 文件 | 作用 |
| --- | --- |
| `backend/Dockerfile.reuse` | 复用远程已有 `rag-school-backend:runtime-base` 镜像，快速部署当前代码 |
| `backend/Dockerfile.lite` | 轻量构建，不安装 PaddleOCR，不安装 LibreOffice |
| `backend/requirements-lite.txt` | 轻量版 Python 依赖 |
| `deploy/docker-compose.remote.yml` | 远程部署专用 Compose，端口避开旧服务 |
| `deploy/remote_init_env.py` | 在远程生成 `.env`，复用服务器已有模型 Key |
| `deploy/remote_health_check.py` | 读取远程 `.env` 中 Token 并验证 internal health |

当前远程实际使用：

```text
docker-compose.remote.yml + Dockerfile.reuse
```

## 6. 首次部署流程

以下命令在本地项目根目录执行。

### 6.1 打包项目

```powershell
tar --exclude='backend/.pytest_cache' `
    --exclude='backend/**/__pycache__' `
    --exclude='backend/**/*.pyc' `
    --exclude='.git' `
    --exclude='.venv' `
    --exclude='.cache' `
    --exclude='rag_java_deploy.tgz' `
    -czf rag_java_deploy.tgz .
```

### 6.2 上传到服务器

```powershell
scp rag_java_deploy.tgz root@47.100.216.222:/tmp/rag_java_deploy.tgz
```

### 6.3 解压到部署目录

```bash
ssh root@47.100.216.222

mkdir -p /app/rag-java-internal
rm -rf /app/rag-java-internal.new
mkdir -p /app/rag-java-internal.new
tar -xzf /tmp/rag_java_deploy.tgz -C /app/rag-java-internal.new
rsync -a --delete /app/rag-java-internal.new/ /app/rag-java-internal/
rm -rf /app/rag-java-internal.new
```

### 6.4 生成远程环境变量

```bash
cd /app/rag-java-internal
python3 deploy/remote_init_env.py
chmod 600 .env
```

该脚本会：

- 从 `/app/.env` 读取已有模型 Key。
- 生成或保留 `RAG_SERVICE_TOKEN`。
- 写入当前项目自己的 `/app/rag-java-internal/.env`。
- 设置 `OCR_ENABLED=false`。
- 设置当前服务端口和 MinIO 地址。

### 6.5 构建镜像

当前推荐使用复用模式：

```bash
cd /app/rag-java-internal/backend
docker build -f Dockerfile.reuse -t rag-java-internal-backend:reuse .
```

如果服务器没有 `rag-school-backend:runtime-base` 镜像，可改用轻量构建：

```bash
docker build -f Dockerfile.lite -t rag-java-internal-backend:lite .
```

轻量构建会联网安装 Python 依赖，服务器网络较慢时耗时较久。

### 6.6 启动服务

```bash
cd /app/rag-java-internal
docker compose -p rag-java-internal -f deploy/docker-compose.remote.yml up -d --no-build
```

查看状态：

```bash
docker compose -p rag-java-internal -f deploy/docker-compose.remote.yml ps
```

## 8. Java 对接配置

Java 后台配置：

```text
RAG_BASE_URL=http://127.0.0.1:18020/internal/rag
RAG_SERVICE_TOKEN=<读取 /app/rag-java-internal/.env 中的 RAG_SERVICE_TOKEN>
```

健康检查：

```http
GET http://127.0.0.1:18020/internal/rag/health
X-RAG-Service-Token: <RAG_SERVICE_TOKEN>
```

问答流式接口：

```http
POST http://127.0.0.1:18020/internal/rag/chat/stream
Content-Type: application/json
Accept: text/event-stream
X-RAG-Service-Token: <RAG_SERVICE_TOKEN>
```

文档处理接口：

```http
POST http://127.0.0.1:18020/internal/rag/documents/process
Content-Type: application/json
X-RAG-Service-Token: <RAG_SERVICE_TOKEN>
```

Java 必须传 `user_context` 和 `access_scope`，Python 才会执行权限过滤后的召回。

## 9. 公网访问和安全组

服务器内部验证已通过，但公网访问新端口可能超时。

如果 Java 不在同一台服务器，需要在阿里云安全组放行：

```text
TCP 18020
```

如果需要外部访问 MinIO：

```text
TCP 19004
TCP 19005
```

生产建议：

- 不要把 `/internal/rag/*` 直接暴露给浏览器。
- 最好只允许 Java 服务器 IP 访问 `18020`。
- 如果必须公网暴露，建议前面加 Nginx + IP 白名单。

## 12. 数据备份

### 12.1 PostgreSQL 备份

PostgreSQL 已改为 Java 统一数据库，不再由本项目的 `rag_java2_postgres`
容器承载。备份应按 Java 现有数据库实例执行，确保包含 Python RAG 表
（如 `documents`、`document_jobs`、`document_chunks`、`retrieval_logs` 等）。

### 12.2 MinIO 数据备份

MinIO 已改为服务器统一服务，不再由本项目的 `rag_java2_minio` 容器承载。
备份应按服务器现有 MinIO 运维方案执行。

### 12.3 代码备份

```bash
mkdir -p /app/rag-java-internal-backups
tar -C /app -czf /app/rag-java-internal-backups/rag-java-internal-$(date +%Y%m%d-%H%M%S).tgz rag-java-internal
```

## 13. 回滚流程

如果只是代码问题：

```bash
cd /app
mv rag-java-internal rag-java-internal.bad.$(date +%Y%m%d-%H%M%S)
tar -xzf /app/rag-java-internal-backups/<备份包>.tgz -C /app

cd /app/rag-java-internal/backend
docker build -f Dockerfile.reuse -t rag-java-internal-backend:reuse .

cd /app/rag-java-internal
docker compose -p rag-java-internal -f deploy/docker-compose.remote.yml up -d --no-build
python3 deploy/remote_health_check.py
```

如果数据库也要回滚，需要先停止服务并恢复对应 SQL 备份，谨慎操作。

## 14. 完整 OCR 版说明

当前轻量版：

```text
OCR_ENABLED=false
不安装 paddleocr
不安装 paddlepaddle
不预下载 OCR 模型
```

如果后续需要扫描 PDF、图片 OCR：

1. 先确保服务器有足够磁盘空间，建议至少预留 `15-20GB`。
2. 改用 `backend/Dockerfile` 构建完整镜像。
3. `.env` 中设置：

```text
OCR_ENABLED=true
OCR_LANG=ch
OCR_USE_GPU=false
```

完整构建命令：

```bash
cd /app/rag-java-internal/backend
docker build -f Dockerfile -t rag-java-internal-backend:full .
```

再将 `deploy/docker-compose.remote.yml` 中 backend/worker 的镜像切到：

```text
rag-java-internal-backend:full
```

完整 OCR 版首次构建可能很慢，失败时优先检查：

```bash
df -h /
docker system df
docker builder prune
```

## 15. 常见问题

### 15.1 internal health 返回 401

原因：

- 没带 `X-RAG-Service-Token`。
- Token 和 `.env` 不一致。

处理：

```bash
grep '^RAG_SERVICE_TOKEN=' /app/rag-java-internal/.env
```

Java 请求头必须带同一个值。

### 15.2 internal health 返回 503

原因：

- `RAG_SERVICE_TOKEN` 为空。
- `RAG_SERVICE_TOKEN=change-me`。

处理：

```bash
cd /app/rag-java-internal
python3 deploy/remote_init_env.py
docker compose -p rag-java-internal -f deploy/docker-compose.remote.yml restart backend worker
```

### 15.3 公网访问超时

如果服务器本机可访问：

```bash
curl http://127.0.0.1:18020/
```

但外部访问：

```text
http://47.100.216.222:18020/
```

超时，通常是阿里云安全组没有放行 `18020`。

处理：

- 阿里云控制台放行 TCP `18020`。
- 或让 Java 部署在同一台服务器并访问 `127.0.0.1:18020`。

### 15.4 文档处理任务不执行

检查 worker：

```bash
docker logs -f rag_java2_worker
```

检查 Redis：

```bash
curl http://127.0.0.1:18020/api/v1/readiness
```

如果 Redis 不正常，重启：

```bash
docker compose -p rag-java-internal -f deploy/docker-compose.remote.yml restart redis worker
```

### 15.5 问答或向量化失败

检查模型 Key 是否配置：

```bash
grep -E '^(DEEPSEEK_API_KEY|EMBEDDING_API_KEY|RERANK_API_KEY)=' /app/rag-java-internal/.env
```

不要在日志和截图中暴露 Key。

### 15.6 构建很慢或卡住

当前服务器网络和磁盘条件有限。

推荐优先使用：

```bash
Dockerfile.reuse
```

不要直接在磁盘紧张时构建完整 PaddleOCR 镜像。
