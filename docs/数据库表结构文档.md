# Python RAG 数据库表结构文档

版本：V1.0  
日期：2026-07-01  
适用项目：`rag_java`

> 调用流程和请求示例见 [Java对接调用流程详版.md](Java对接调用流程详版.md)。本文主要说明 Python RAG 侧数据库字段和表归属。

## 1. 总体说明

当前项目使用 PostgreSQL + pgvector。

必需扩展：

```sql
CREATE EXTENSION IF NOT EXISTS vector;
CREATE EXTENSION IF NOT EXISTS pg_trgm;
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";
```

当前代码中的表名沿用原 RAG 项目，例如：

```text
documents
document_chunks
chunk_embeddings
conversations
retrieval_logs
```

如果和 Java 共用同一个 PostgreSQL 实例，建议二选一：

1. Python RAG 使用独立 schema，例如 `rag.documents`、`rag.document_chunks`。
2. Python RAG 表统一加前缀，例如 `rag_documents`、`rag_document_chunks`。

不建议 Java 和 Python 随意混写同一张表。每张表必须明确唯一写入方。

常用状态：

| 状态 | 说明 |
| --- | --- |
| `uploaded` | 已创建，待处理 |
| `parsed` | 已解析 |
| `chunked` | 已切片 |
| `indexed` | 已向量化，可检索 |
| `failed` | 处理失败 |

关键索引：

| 索引 | 字段 |
| --- | --- |
| `idx_documents_status` | `status` |
| `idx_documents_hash` | `file_hash` |
| `idx_documents_java_attach_id` | `java_attach_id` |
| `idx_documents_publish_dept` | `publish_dept_id` |
| `idx_documents_visible_in_chat` | `visible_in_chat` |
| `idx_documents_publish_scope` | `publish_scope` |
| `idx_documents_allowed_dept_ids` | `allowed_dept_ids` GIN |
| `idx_documents_allowed_user_ids` | `allowed_user_ids` GIN |
| `idx_documents_knowledge_base` | `knowledge_base` |

问答检索前会先按以下条件筛文档：

```sql
deleted_at IS NULL
AND visible_in_chat = true
AND status = 'indexed'
AND (
  publish_scope = 'public'
  OR (publish_scope = 'dept' AND publish_dept_id = ANY(:allowed_dept_ids))
  OR (publish_scope = 'private' AND owner_user_id = :user_id)
  OR (publish_scope = 'custom' AND (
    owner_user_id = :user_id
    OR allowed_user_ids @> ARRAY[:user_id]
    OR allowed_dept_ids && :allowed_dept_ids
  ))
)
```

## 4. Java 权限过滤与表字段关系

### 4.1 部门权限

如果规则是“哪个部门发布的资料，只有该部门用户或管理员可以检索”，流程如下：

```text
Java 用户表保存用户部门
Java 文档表保存文档发布部门、可见范围、指定部门、指定人员
Java 调 Python 时传 user_id、allowed_dept_ids、allowed_attach_ids
Python 用这些字段过滤 documents.publish_scope、publish_dept_id、allowed_dept_ids、allowed_user_ids
```

Python 实际过滤条件：

```sql
SELECT id
FROM documents
WHERE deleted_at IS NULL
  AND visible_in_chat = true
  AND status = 'indexed'
  AND (
    publish_scope = 'public'
    OR (publish_scope = 'dept' AND publish_dept_id = ANY(:allowed_dept_ids))
    OR (publish_scope = 'private' AND owner_user_id = :user_id)
    OR (publish_scope = 'custom' AND (
      owner_user_id = :user_id
      OR allowed_user_ids @> ARRAY[:user_id]
      OR allowed_dept_ids && :allowed_dept_ids
    ))
  )
```

### 4.2 知识库权限

Java 如果按知识库授权，则调用问答接口时传：

```json
{
  "allowed_knowledge_ids": ["kb_student", "kb_policy"]
}
```

Python 叠加过滤：

```sql
AND knowledge_base = ANY(:allowed_knowledge_ids)
```

### 4.3 文档级权限

Java 如果按具体文档授权，则传：

```json
{
  "allowed_attach_ids": [101, 102],
  "deny_attach_ids": [999]
}
```

Python 叠加过滤：

```sql
AND java_attach_id = ANY(:allowed_attach_ids)
AND java_attach_id <> ALL(:deny_attach_ids)
```

## 5. 共库部署建议

Java 和 Python 可以共用一个 PostgreSQL 实例，但建议：

1. Java 业务表和 Python RAG 表隔离。
2. Java 不直接写 Python RAG 表。
3. Python 不直接写 Java 业务表。
4. 双方通过接口同步状态。
5. 如需 Java 读 RAG 片段或日志，建议只读查询或由 Python 提供接口。

推荐 schema：


## 6. 当前需要注意的结构问题

| 问题 | 当前状态 | 建议 |
| --- | --- | --- |
| 表名无 `rag_` 前缀 | 当前沿用原项目表名 | 与 Java 共库前建议加 schema 或前缀 |
| `publish_scope` 已存在 | 支持 `public`、`dept`、`private`、`custom` | Java 发布文档时必须传准 |
| Java 消息 ID 未入表 | `message_id` 接口字段当前未保存 | 如需对账，新增 `java_message_id` |
| Java 状态回写表未定 | Python 只保存自己的任务状态 | Java 可轮询，也可后续加回调 |
| `admins` 表仍存在 | 原系统管理后台遗留 | Java 接入后不作为主鉴权 |
