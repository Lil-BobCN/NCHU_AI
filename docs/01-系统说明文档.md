# 系统说明文档

## 一、系统目标

Java Internal RAG Service 是一个面向 Java 后台的内部 RAG 能力服务。它不直接面对前端用户，而是由 Java 后台在完成登录鉴权、权限计算和业务编排后调用。

系统能力包括：

- 文档接入：接收 Java 传来的附件 ID、知识库 ID、文件元数据和对象存储位置。
- 文档处理：从 MinIO 读取文件，执行解析、OCR、切片、向量化和索引入库。
- 智能问答：根据用户问题和权限范围召回知识片段，调用大模型生成回答。
- 引用溯源：返回引用文档、页码、章节、图片和下载链接。
- 会话管理：保存会话、消息、摘要、上下文状态。
- 反馈闭环：记录用户对回答的纠错反馈。
- 评测能力：维护评测用例和评测运行记录。

## 二、系统边界

Java 端负责：

- 前端页面和交互。
- 登录、Sa-Token 会话、用户、部门、角色。
- 文档业务表、文件上传入口、附件 ID。
- 当前用户可访问范围计算。
- 业务会话入口和前端展示编排。

Python RAG 端负责：

- 校验 Java 传入的 Sa-Token JWT。
- 保存 RAG 侧文档索引、解析结果、切片、向量、问答日志。
- 根据 Java 传入的 `access_scope` 做二次过滤。
- 调用 embedding、rerank、chat 模型。
- 返回答案、引用、推荐追问和检索轨迹。

## 三、总体架构

```text
前端
  |
  v
Java 后台
  | 1. 登录鉴权、权限计算、文档业务记录
  | 2. Authorization: Bearer <Sa-Token JWT>
  | 3. user_context + access_scope
  v
Python RAG Service (FastAPI)
  |-- PostgreSQL + pgvector：文档索引、向量、会话、日志、反馈
  |-- Redis：后台任务队列、检索缓存、向量缓存、答案缓存
  |-- MinIO：原始文件、解析结果、图片预览
  |-- DeepSeek：对话模型
  |-- DashScope：Embedding 和 Rerank
```

## 四、核心业务流程

### 1. 文档入库流程

1. Java 完成文件上传，将原始文件放入 MinIO 或可被 Python 读取的对象存储。
2. Java 调用 `POST /internal/rag/documents/process`，传入 `attach_id`、文件名、hash、bucket、object_key、知识库和可见范围。
3. Python 在 `documents` 表中按 `java_attach_id` 新增或更新文档。
4. 如果 `auto_process=true`，Python 创建 `document_jobs` 任务，并将任务写入 Redis 队列。
5. worker 从 Redis 队列取任务，执行 `DocumentPipeline`：
   - 从 MinIO 读取文件。
   - 解析正文、表格、图片和 OCR 内容。
   - 保存解析 Markdown 到 MinIO。
   - 写入 `document_parse_results`。
   - 切片写入 `document_chunks`。
   - 生成 embedding 写入 `chunk_embeddings`。
   - 文档状态更新为 `indexed`。
6. Java 可调用 `GET /internal/rag/jobs/{job_id}` 或 `GET /internal/rag/documents/{attach_id}` 查询进度和状态。

### 2. 问答流程

1. Java 根据当前登录用户计算 `user_context` 和 `access_scope`。
2. Java 调用 `POST /internal/rag/chat` 或 `POST /internal/rag/chat/stream`。
3. Python 验证 Sa-Token JWT。
4. Python 根据 `access_scope` 查询当前用户可访问的文档 ID。
5. `ChatService` 读取会话历史，必要时改写追问。
6. `RetrievalService` 执行混合召回：
   - 向量召回。
   - 关键词召回。
   - QA Pair 直接命中。
   - RRF 融合。
   - Rerank 重排。
   - 相邻上下文扩展。
   - 引用来源生成。
7. `ModelService` 调用聊天模型生成答案。
8. 结果写入 `conversation_messages` 和 `retrieval_logs`。
9. 接口返回答案、引用、推荐问题、消息 ID 和检索轨迹。

### 3. 权限过滤流程

文档入库时记录：

- `publish_scope`：`public`、`dept`、`private`、`custom`。
- `publish_dept_id`：发布部门。
- `owner_user_id`：归属用户。
- `allowed_dept_ids`：可见部门列表。
- `allowed_user_ids`：可见用户列表。
- `visible_in_chat`：是否允许进入问答检索。

问答时 Java 传入：

- `user_context.user_id`：当前用户。
- `user_context.dept_id`：当前部门。
- `access_scope.scope_mode`：`dept`、`all_public`、`custom`、`admin_all`。
- `access_scope.allowed_dept_ids`：允许访问的部门。
- `access_scope.allowed_knowledge_ids`：允许访问的知识库。
- `access_scope.allowed_attach_ids`：允许访问的附件 ID。
- `access_scope.deny_attach_ids`：显式排除的附件 ID。

Python 只会在已过滤出的文档范围内执行召回，避免无权限文档进入模型上下文。

## 五、主要功能模块

- 健康检查：`health.py`、`internal.py`。
- 鉴权：`deps.py`、`security.py`。
- 文档接口：`documents.py`、`internal.py`。
- 文档流水线：`document_pipeline.py`。
- 文档解析：`parse_service.py`、`ocr_service.py`。
- 切片：`chunk_service.py`。
- 模型调用：`model_service.py`、`rerank_service.py`。
- 检索：`retrieval_service.py`。
- 问答：`chat_service.py`。
- 对象存储：`minio_service.py`。
- Redis 队列和缓存：`redis_service.py`、`task_queue_service.py`。
- 反馈：`feedback.py`。
- 评测：`evaluation.py`。
- 数据模型：`models.py`。

## 六、文件类型支持

当前支持：

- PDF：PyMuPDF 解析，必要时 OCR。
- Word：`.docx` 直接解析，`.doc` 可走 LibreOffice 转换。
- Excel：`.xlsx`、`.xlsm`、`.xls`。
- 文本：`.txt`、`.md`。
- 图片：`.jpg`、`.jpeg`、`.png`、`.bmp`、`.tif`、`.tiff`，使用 OCR。
- 压缩包：`.zip`、`.rar`，支持安全解压和导入内部文件。

## 七、外部依赖

- PostgreSQL 16，需安装 `pgvector`、`pg_trgm`、`uuid-ossp` 扩展。
- Redis 7。
- MinIO。
- DeepSeek 兼容 OpenAI 的 Chat Completions API。
- DashScope OpenAI 兼容 Embedding API。
- DashScope Rerank API。
- PaddleOCR 和 PaddlePaddle。
- LibreOffice，用于旧版 Office 文件转换。

## 八、运行端口

本地 compose 默认：

- FastAPI：`127.0.0.1:8020 -> 8000`
- PostgreSQL：`127.0.0.1:5434 -> 5432`
- Redis：`127.0.0.1:6381 -> 6379`
- MinIO API：`9004 -> 9000`
- MinIO Console：`9005 -> 9001`

远程 compose 默认：

- FastAPI：`0.0.0.0:18020 -> 8000`
- Redis：`127.0.0.1:16381 -> 6379`
- PostgreSQL：不在 compose 中启动，使用 Java 服务器已有数据库。
