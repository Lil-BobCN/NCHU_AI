# 技术框架文档

## 1. 总体架构

系统由前端、后端 API、后台 worker、PostgreSQL、Redis、MinIO 和外部模型服务组成。

```text
Browser
  |
  | HTTP/SSE
  v
Frontend Vue/Nginx
  |
  | /api proxy
  v
FastAPI Backend
  |         |           |
  |         |           +--> DeepSeek Chat Model
  |         +--------------> DashScope Embedding/Rerank
  |
  +--> PostgreSQL + pgvector
  +--> Redis
  +--> MinIO
             ^
             |
Background Worker
```

## 4. 数据流

### 4.1 存储流

| 数据 | 存储位置 |
| --- | --- |
| 管理员账号 | PostgreSQL `admins` |
| 文档元数据 | PostgreSQL `documents` |
| 原始文件 | MinIO `rag-documents` |
| 解析文本/Markdown | PostgreSQL `document_parse_results` + MinIO `rag-parsed` |
| 文档切片 | PostgreSQL `document_chunks` |
| 文档向量 | PostgreSQL `chunk_embeddings` |
| QA 对 | PostgreSQL `qa_pairs` |
| QA 向量 | PostgreSQL `qa_pair_embeddings` |
| 会话消息 | PostgreSQL `conversations`、`conversation_messages` |
| 检索日志 | PostgreSQL `retrieval_logs` |
| 回答反馈 | PostgreSQL `answer_feedbacks` |
| 后台任务 | PostgreSQL `document_jobs` + Redis 队列 |
| 缓存 | Redis |

### 4.2 文档任务流

Redis 队列中的任务类型：

| 任务类型 | 处理逻辑 |
| --- | --- |
| `document_full_pipeline` | 解析、切片、向量化 |
| `document_rechunk` | 重切片并向量化 |
| `document_reembed` | 重向量化 |
| `document_convert_office` | 旧 Office 转换 |
| `document_extract_archive` | 压缩包导入 |
| `document_qa_generate` | 从文档生成 QA 对 |
| `qa_embedding_sync` | 同步 QA 向量 |
| `evaluation_run` | 运行评估批次 |

worker 入口是：

```text
backend/app/workers/document_worker.py
```

## 5. RAG 检索架构

### 5.1 召回

系统采用多路召回：

| 召回方式 | 数据源 | 适用场景 |
| --- | --- | --- |
| 向量召回 | `chunk_embeddings` | 语义相关问题 |
| 关键词召回 | `document_chunks.search_vector` 和文本匹配 | 精确术语、编号、金额 |
| QA 召回 | `qa_pairs` 和 `qa_pair_embeddings` | 高频标准问答 |

### 5.2 重排

召回结果先去重、过滤和融合，再执行 rerank。启用远程 rerank 时调用 DashScope；失败或关闭时使用本地权重策略兜底。

### 5.3 回答

`ChatService` 将最终上下文、引用来源和历史信息组装为 prompt，调用 DeepSeek 生成回答。流式接口通过 SSE 输出：

| 事件 | 说明 |
| --- | --- |
| `message_start` | 会话和消息 ID |
| `retrieval_start` | 检索开始 |
| `retrieval_done` | 检索完成 |
| `delta` | 回答增量 |
| `citations` | 引用来源 |
| `suggested_questions` | 推荐追问 |
| `message_end` | 消息结束和耗时 |

## 6. 缓存和并发

| 能力 | 配置 |
| --- | --- |
| 检索缓存 | `RETRIEVAL_CACHE_ENABLED`、`RETRIEVAL_CACHE_TTL_SECONDS` |
| 回答缓存 | `ANSWER_CACHE_ENABLED`、`ANSWER_CACHE_TTL_SECONDS` |
| embedding 缓存 | `EMBEDDING_CACHE_ENABLED`、`EMBEDDING_CACHE_TTL_SECONDS` |
| 模型并发 | `MODEL_MAX_CONCURRENT_REQUESTS` |
| 聊天并发 | `CHAT_MAX_CONCURRENT_REQUESTS`、`CHAT_GLOBAL_MAX_CONCURRENT_REQUESTS` |
| worker 并发 | `BACKGROUND_WORKER_CONCURRENCY` |

并发建议：

1. API worker 数量由 `WEB_CONCURRENCY` 控制。
2. 文档处理是 CPU/IO/模型混合负载，worker 并发不宜盲目调大。
3. embedding 和 rerank 都可能受供应商 QPS 限制，需要按实际额度调整。

## 7. 前端架构

前端是 Vue 单页应用：

| 模块 | 说明 |
| --- | --- |
| Router | 页面路由和登录跳转 |
| API Client | Axios 实例、token 注入、错误处理 |
| Chat Store | SSE 状态、消息追加、引用和推荐追问 |
| Views | 文档、聊天、QA、评估、检索调试 |
| AppShell | 统一导航和页面框架 |

生产容器内使用 Nginx 服务静态文件，并代理 API 和 MinIO 路径。

## 8. 安全设计

当前安全设计：

| 项 | 说明 |
| --- | --- |
| 鉴权 | JWT Bearer Token |
| 密码 | passlib 哈希 |
| 上传限制 | 扩展名和大小限制 |
| 路径安全 | MinIO object key 由后端生成 |
| 压缩包导入 | 需要限制可导入文件和路径穿越 |
| 敏感配置 | `.env` 不进入交付包 |

生产建议：

1. 使用 HTTPS。
2. 更换默认 MinIO、PostgreSQL、管理员密码。
3. 限制后端、数据库、Redis、MinIO 的公网暴露。
4. 为模型 key 设置额度和访问控制。
5. 配置日志脱敏策略。

## 9. 可扩展方向

| 方向 | 建议 |
| --- | --- |
| 多用户权限 | 增加用户、角色、知识库权限表 |
| 多知识库隔离 | 检索和文档 API 增加强制 scope |
| 更强任务队列 | 将 Redis 简单队列替换为 Celery/RQ/Arq 等 |
| 召回优化 | 增加 BM25、hybrid search、结构化表格检索 |
| 评估体系 | 增加答案正确性、引用准确性、无依据拒答指标 |
| 文件预览 | 增加受控下载和签名 URL |
