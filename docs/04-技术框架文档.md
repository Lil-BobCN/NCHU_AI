# 技术框架文档

## 一、技术栈

后端框架：

- FastAPI：HTTP API 和 SSE 流式响应。
- Uvicorn：ASGI 服务。
- Pydantic v2：请求、配置和字段校验。

数据库：

- PostgreSQL 16。
- SQLAlchemy AsyncIO。
- asyncpg。
- pgvector：向量检索。
- pg_trgm：文本相似度和 QA 匹配。
- Alembic：结构迁移。

缓存和任务：

- Redis：后台任务队列、任务进度缓存、embedding 缓存、检索缓存、答案缓存。

对象存储：

- MinIO：原始文档、解析结果、图片资产。

模型服务：

- DeepSeek OpenAI-compatible API：聊天模型。
- DashScope OpenAI-compatible API：Embedding。
- DashScope Rerank API：文本重排。

文档解析：

- PyMuPDF：PDF。
- python-docx：DOCX。
- openpyxl、xlrd：Excel。
- PaddleOCR、PaddlePaddle：图片和扫描件 OCR。
- LibreOffice：旧版 Office 转换。

测试：

- pytest。
- FastAPI TestClient 或相关测试工具。

## 二、应用启动框架

入口：

```text
backend/app/main.py
```

启动时：

- 创建 FastAPI 应用。
- 添加 CORS 中间件。
- 挂载普通 API：`/api/v1`。
- 挂载 Java 内部 API：`/internal/rag`。
- 退出时关闭 rerank、model、redis 客户端。

## 四、RAG 技术链路

### 1. 文档解析

`ParseService` 根据扩展名选择解析器：

- PDF：抽取文本，扫描件或低文本页触发 OCR。
- DOCX：段落、表格、图片 OCR。
- DOC：通过 LibreOffice 转换后再处理。
- XLSX/XLSM/XLS：表格识别、表头推断、大表采样。
- 图片：OCR。
- 压缩包：先作为容器文档记录，再支持解压导入内部文件。

解析结果写入：

- `document_parse_results.content_text`
- `document_parse_results.content_md`
- `rag-parsed` bucket
- 图片资产写入 `rag-preview` bucket

### 2. 文档切片

`ChunkService` 负责按配置切片：

- 默认 `CHUNK_SIZE=800`。
- 默认 `CHUNK_OVERLAP=120`。
- 支持表格 chunk。
- 支持 parent chunk，用于章节级上下文扩展。

切片写入：

- `document_chunks`
- `search_vector` 用于关键词召回。

### 3. 向量化

`ModelService.embed()` 调用 embedding 模型。

向量写入：

- `chunk_embeddings.embedding`
- `qa_pair_embeddings.embedding`

默认维度：

```text
EMBEDDING_DIMENSION=1024
```

### 4. 混合召回

`RetrievalService.search()` 包含：

- 向量召回：基于 pgvector cosine 距离。
- 关键词召回：基于 `tsvector`。
- QA 召回：基于 QA Pair exact、trigram、向量匹配。
- RRF 融合：合并多路召回。
- Rerank：调用 DashScope Rerank。
- 业务规则过滤：去除黑名单文档、异常 URL 编码文件、无权限文档。
- 上下文扩展：相邻 chunk、父子 chunk、政策类覆盖。
- 引用生成：文档、页码、章节、图片、下载链接。

### 5. 问答生成

`ChatService` 负责：

- 创建或复用会话。
- 记录用户消息。
- 读取最近历史和会话摘要。
- 识别寒暄或追问。
- 构造检索 query。
- 调用 RetrievalService。
- 调用 Chat Model 流式生成。
- 生成引用和推荐追问。
- 保存 assistant 消息和 retrieval log。

流式接口使用 Server-Sent Events，事件包括：

- `message_start`
- `retrieval_start`
- `retrieval`
- `retrieval_done`
- `delta`
- `citations`
- `suggested_questions`
- `message_end`

## 五、并发和缓存

并发控制：

- `model_call_slot`
- `embedding_call_slot`
- `chat_max_concurrent_requests`
- `model_max_concurrent_requests`
- `embedding_max_concurrent_requests`
- 可选分布式聊天并发控制。

缓存：

- Embedding 缓存：默认开启，TTL 7 天。
- Retrieval 缓存：默认开启，TTL 30 分钟。
- Answer 缓存：默认开启，TTL 1 小时。

缓存失效依赖：

- 知识库版本 `knowledge_base_versions`。
- 文档更新时间和数量。
- 模型名称和 RAG 参数。

## 六、安全框架

Java internal API 使用 Sa-Token JWT：

- Header：`Authorization: Bearer <token>`。
- 密钥：`SA_TOKEN_JWT_SECRET`。
- 算法：`SA_TOKEN_JWT_ALGORITHM`，默认 `HS256`。
- payload 必须包含 `loginId` 和 `userId`。
- 如果包含 `eff` 和 `timeout`，Python 会校验有效期。

普通管理 API 同时支持本地 admin JWT 和 Java Sa-Token fallback。

权限防线：

1. Java 端做用户权限和部门范围计算。
2. Python 端根据 `access_scope` 做检索前过滤。
3. 检索 SQL 只查询 `indexed`、未删除、可见文档。
4. 进入模型上下文的内容已经经过权限过滤。

## 七、部署框架

本地：

- `deploy/docker-compose.yml`
- 启动 PostgreSQL、Redis、MinIO、backend、worker。

远程：

- `deploy/docker-compose.remote.yml`
- 使用外部 PostgreSQL。
- 启动 Redis、backend、worker。

worker 和 backend 使用同一份代码，但命令不同：

```text
backend: uvicorn app.main:app
worker: python -m app.workers.document_worker
```
