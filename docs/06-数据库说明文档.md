# 数据库说明文档

## 一、数据库类型

使用 PostgreSQL，推荐版本 16。

需要扩展：

```sql
CREATE EXTENSION IF NOT EXISTS vector;
CREATE EXTENSION IF NOT EXISTS pg_trgm;
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";
```

初始化 SQL：

```text
backend/sql/001_init.sql
```

ORM 模型：

```text
backend/app/db/models.py
```

迁移目录：

```text
backend/alembic/versions/
```

## 二、核心表

### admins

本地管理后台账号表。

主要字段：

- `username`
- `password_hash`
- `display_name`
- `is_active`
- `last_login_at`

### documents

RAG 文档主表。

关键字段：

- `id`：RAG 文档 UUID。
- `java_attach_id`：Java 附件 ID，唯一。
- `java_doc_id`：Java 业务文档 ID。
- `knowledge_base`：知识库 ID。
- `publish_dept_id`：发布部门。
- `owner_user_id`：归属用户。
- `visible_in_chat`：是否进入问答。
- `publish_scope`：可见范围。
- `allowed_dept_ids`：允许部门。
- `allowed_user_ids`：允许用户。
- `file_name`、`file_ext`、`mime_type`、`file_size`、`file_hash`：文件元数据。
- `storage_bucket`、`storage_object_key`：对象存储位置。
- `status`：处理状态。
- `parse_quality_score`：解析质量评分。
- `error_message`：失败原因。
- `deleted_at`：软删除时间。

常用状态：

- `uploaded`：已登记，待处理。
- `parsed`：已解析。
- `chunked`：已切片。
- `indexed`：已向量化，可检索。
- `failed`：处理失败。
- `converted`：旧 Office 已转换。
- `extracted`：压缩包已解压导入。
- `needs_conversion`：需要转换。

### knowledge_base_versions

知识库版本表，用于检索缓存失效。

字段：

- `scope`：知识库范围。
- `version`：版本号。
- `changed_at`：更新时间。
- `reason`：变更原因。
- `document_id`：触发变更的文档。

文档切片、重建、索引、删除时应更新版本。

### document_jobs

文档异步任务表。

字段：

- `document_id`
- `job_type`
- `status`
- `progress`
- `message`
- `error_message`
- `retry_count`
- `params`
- `result`
- `started_at`
- `finished_at`

常见任务类型：

- `document_full_pipeline`
- `document_rechunk`
- `document_reembed`
- `document_convert_office`
- `document_extract_archive`
- `document_qa_generate`
- `qa_embedding_sync`
- `evaluation_run`

### document_parse_results

解析结果表。

字段：

- `document_id`
- `parser_name`
- `parser_version`
- `content_text`
- `content_md`
- `content_object_key`
- `page_count`
- `quality_score`
- `parse_meta`

### document_chunks

文档切片表。

字段：

- `document_id`
- `parent_chunk_id`
- `chunk_no`
- `chunk_type`
- `content`
- `content_hash`
- `token_count`
- `char_count`
- `page_start`
- `page_end`
- `section_path`
- `metadata`
- `search_vector`
- `is_active`

`search_vector` 用于 PostgreSQL 关键词召回。

### chunk_embeddings

切片向量表。该表在 SQL 初始化文件中创建，ORM 中未显式定义模型，主要通过 SQL 写入和查询。

字段：

- `chunk_id`
- `document_id`
- `embedding vector(1024)`
- `embedding_model`
- `embedding_provider`
- `content_hash`

索引：

- HNSW vector cosine 索引。

### qa_pairs

## 四、状态流转

文档完整处理：

```text
uploaded -> parsed -> chunked -> indexed
```

失败：

```text
uploaded/parsed/chunked -> failed
```

旧 Office：

```text
uploaded -> needs_conversion -> converted -> 子文档 uploaded -> indexed
```

压缩包：

```text
uploaded -> extracted -> 子文档 uploaded -> indexed
```

删除：

```text
任意状态 -> deleted_at 非空
```

## 五、数据归属说明

Java 侧保留：

- 用户、部门、角色。
- 附件业务主记录。
- 前端业务会话入口。
- 审批、菜单、权限等业务数据。

Python 侧保留：

- RAG 文档索引副本。
- 解析结果、切片、向量。
- RAG 会话消息。
- 检索日志、引用、反馈。
- 评测数据。

`java_attach_id` 是 Java 和 Python 文档数据的核心关联键。

## 六、生产维护建议

- 定期清理软删除文档的对象存储残留。
- 定期分析 `retrieval_logs`，优化召回参数和黑名单。
- 关注 `document_jobs.failed` 数量。
- 对 `chunk_embeddings` 和 `qa_pair_embeddings` 的向量维度变更要做完整迁移。
- 数据库备份必须覆盖向量表，否则恢复后无法问答。
