# 部署文档

## 1. 环境要求

| 组件 | 建议版本 | 说明 |
| --- | --- | --- |
| Python | 3.11 | 后端运行环境 |
| Node.js | 20+ 或 22 | 前端构建环境 |
| Docker | 24+ | 推荐部署方式 |
| Docker Compose | v2 | 启动数据库、Redis、MinIO、前后端 |
| PostgreSQL | 16 + pgvector | 向量检索和业务数据 |
| Redis | 7 | 后台任务队列、缓存、进度 |
| MinIO | latest | 原始文档和解析文件存储 |
| LibreOffice | 服务器部署需安装 | 旧 `.doc/.xls` 转换 |

推荐优先使用 Docker Compose 部署，因为容器内已经包含 Python、OCR、LibreOffice、前后端构建环境。

## 2. 环境变量

从模板生成正式配置：

```powershell
Copy-Item .env.example .env
```

必须修改的变量：

| 变量 | 说明 |
| --- | --- |
| `DEEPSEEK_API_KEY` | DeepSeek 问答模型密钥 |
| `EMBEDDING_API_KEY` | DashScope embedding 密钥 |
| `RERANK_API_KEY` | DashScope rerank 密钥 |
| `JWT_SECRET_KEY` | JWT 签名密钥，生产环境必须使用强随机值 |
| `ADMIN_USERNAME` | 初始管理员账号 |
| `ADMIN_PASSWORD` | 初始管理员密码 |
| `DATABASE_URL` | 后端数据库连接 |
| `REDIS_URL` | Redis 连接 |
| `MINIO_ENDPOINT` | 后端访问 MinIO 的地址 |
| `MINIO_PUBLIC_BASE_URL` | 前端和用户访问文件的公开地址 |

生产环境建议修改的变量：

| 变量 | 建议 |
| --- | --- |
| `MINIO_ACCESS_KEY` / `MINIO_SECRET_KEY` | 不使用默认 `minioadmin` |
| `CHAT_MODEL` | 按模型可用性和成本确认 |
| `WEB_CONCURRENCY` | 按 CPU 和模型并发调整 |
| `BACKGROUND_WORKER_CONCURRENCY` | 文档处理较重，默认 1，确认资源后再提高 |
| `OCR_USE_GPU` | 有 GPU 环境再开启 |

## 3. Docker 一键部署

在项目根目录执行：

```powershell
docker compose -f deploy/docker-compose.yml up --build -d
```

初始化数据库迁移和管理员：

```powershell
docker compose -f deploy/docker-compose.yml exec backend python -m alembic -c /app/alembic.ini upgrade head
docker compose -f deploy/docker-compose.yml exec backend python -m app.init_admin
```

查看容器状态：

```powershell
docker compose -f deploy/docker-compose.yml ps
```

查看日志：

```powershell
docker compose -f deploy/docker-compose.yml logs -f backend
docker compose -f deploy/docker-compose.yml logs -f worker
docker compose -f deploy/docker-compose.yml logs -f frontend
```

访问地址：

| 服务 | 地址 |
| --- | --- |
| 前端 | `http://服务器IP/` |
| 后端健康检查 | `http://服务器IP/api/v1/health` |
| Swagger | `http://服务器IP/api/v1` 前缀下的接口可通过后端端口访问，直连为 `http://服务器IP:8010/docs` |
| MinIO Console | `http://服务器IP:9003` |

说明：`deploy/docker-compose.yml` 中前端服务把宿主机 `80` 端口映射到容器 `5173`，Nginx 同时代理 `/api/` 和 MinIO 文件路径。

## 4. 本地开发部署

启动基础依赖：

```powershell
docker compose -f deploy/docker-compose.yml up -d postgres redis minio
```

创建后端虚拟环境并安装依赖：

```powershell
python -m venv .venv311
.\.venv311\Scripts\python.exe -m pip install -U pip
.\.venv311\Scripts\python.exe -m pip install -r backend\requirements.txt
```

初始化数据库：

```powershell
$env:PYTHONPATH='backend'
.\.venv311\Scripts\python.exe -m alembic -c backend\alembic.ini upgrade head
.\.venv311\Scripts\python.exe -m app.init_admin
```

安装前端依赖：

```powershell
npm --prefix frontend install
```

启动服务：

```powershell
.\scripts\run-backend-dev.cmd
.\scripts\run-frontend-dev.cmd
```

本地地址：

| 服务 | 地址 |
| --- | --- |
| 前端 | `http://127.0.0.1:5173` |
| 后端 | `http://127.0.0.1:8010` |
| API 文档 | `http://127.0.0.1:8010/docs` |

本地开发时如需要处理上传后的文档，还要单独启动 worker：

```powershell
$env:PYTHONPATH='backend'
.\.venv311\Scripts\python.exe -m app.workers.document_worker
```

## 5. 离线部署思路

交付包保留了 `deploy/docker-compose.offline.yml` 和离线更新 Dockerfile。推荐流程：

1. 在有网环境构建镜像：

```powershell
docker build -t deploy-backend:latest -f deploy/Dockerfile.backend.offline-update backend
docker build -t deploy-frontend:latest -f deploy/Dockerfile.frontend.offline-update frontend
```

2. 导出镜像：

```powershell
docker save deploy-backend:latest -o deploy-backend.tar
docker save deploy-frontend:latest -o deploy-frontend.tar
```

3. 拷贝到离线服务器后导入：

```powershell
docker load -i deploy-backend.tar
docker load -i deploy-frontend.tar
```

4. 使用离线 Compose 启动：

```powershell
docker compose -f deploy/docker-compose.offline.yml up -d
```

## 6. 反向代理和域名

如果生产环境需要通过域名访问，建议：

1. 域名指向前端 Nginx。
2. 前端 Nginx 代理 `/api/` 到后端 `backend:8000`。
3. 前端 Nginx 代理 `/rag-documents/`、`/rag-parsed/`、`/rag-preview/` 到 MinIO。
4. `.env` 中 `MINIO_PUBLIC_BASE_URL` 设置为用户浏览器可访问的域名，例如 `https://rag.example.com`。
5. `.env` 中 `APP_PUBLIC_BASE_URL` 可设置为前端域名，用于生成外部链接。

## 7. 发布检查

部署完成后按顺序检查：

```powershell
curl http://127.0.0.1:8010/
curl http://127.0.0.1:8010/api/v1/health
```

健康检查期望返回：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "api": "ok",
    "postgres": "ok",
    "redis": "ok",
    "minio": "ok"
  }
}
```

前端验证：

1. 打开前端页面。
2. 使用管理员账号登录。
3. 上传小文件，确认生成后台任务。
4. 查看 worker 日志，确认任务执行完成。
5. 在检索调试中查询文件内容。
6. 在聊天页提问，确认回答和引用来源。

## 8. 备份和恢复

PostgreSQL 备份：

```powershell
docker exec rag_postgres pg_dump -U rag -d rag -Fc -f /tmp/rag.dump
docker cp rag_postgres:/tmp/rag.dump .\rag.dump
```

PostgreSQL 恢复：

```powershell
docker cp .\rag.dump rag_postgres:/tmp/rag.dump
docker exec rag_postgres pg_restore -U rag -d rag --clean --if-exists /tmp/rag.dump
```

MinIO 备份建议使用 MinIO Client `mc mirror`：

```powershell
mc alias set rag http://127.0.0.1:9002 minioadmin minioadmin
mc mirror rag/rag-documents .\backup\rag-documents
mc mirror rag/rag-parsed .\backup\rag-parsed
mc mirror rag/rag-preview .\backup\rag-preview
```

Redis 通常不作为最终数据源，但如果要迁移任务队列和缓存，可按运维策略开启 RDB/AOF 或停机后迁移数据卷。

## 9. 回滚建议

1. 保留上一个可用镜像标签，例如 `deploy-backend:20260710`。
2. 发布前备份 PostgreSQL 和 MinIO。
3. 如果只更新前端，优先回滚 `frontend` 镜像。
4. 如果更新后端并包含数据库迁移，回滚前确认 Alembic 迁移是否可逆。
5. RAG 模型配置变更应先在测试环境跑评估样本，确认召回和回答质量后再上线。
