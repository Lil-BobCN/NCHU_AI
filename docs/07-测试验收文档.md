## 三、交付验收用例

### 1. 服务启动验收

验收步骤：

1. 准备 `.env`。
2. 启动 backend 和 worker。
3. 调用 `/`。
4. 调用 `/api/v1/health`。
5. 使用 Java JWT 调用 `/internal/rag/health`。

通过标准：

- 服务返回 200。
- internal health 返回 `{code:0}`。
- backend 和 worker 日志无启动异常。

### 2. Java 鉴权验收

验收步骤：

1. 使用正确 Sa-Token JWT 调用 internal health。
2. 使用错误密钥签发的 JWT 调用。
3. 使用过期 JWT 调用。
4. 不带 Authorization 调用。

通过标准：

- 正确 token 成功。
- 错误、过期、缺失 token 返回 401 或对应错误。

### 3. 文档入库验收

验收步骤：

1. 上传一个小型 txt 或 pdf 到 MinIO。
2. Java 调用 `/internal/rag/documents/process`。
3. 轮询 `/internal/rag/jobs/{job_id}`。
4. 查询 `/internal/rag/documents/{attach_id}`。
5. 检查数据库 `documents`、`document_parse_results`、`document_chunks`、`chunk_embeddings`。

通过标准：

- 任务状态最终为 `succeeded`。
- 文档状态为 `indexed`。
- 切片和向量数量大于 0。

### 4. 权限过滤验收

验收步骤：

1. 准备一篇 `publish_scope=dept` 的文档，发布部门为 A。
2. 使用部门 A 用户提问。
3. 使用部门 B 用户提问。
4. 使用 `admin_all` 用户提问。
5. 使用 `deny_attach_ids` 排除该文档后提问。

通过标准：

- 部门 A 可召回。
- 部门 B 不可召回。
- 管理员可召回。
- 显式 deny 后不可召回。

### 5. 问答验收

验收步骤：

1. 调用 `/internal/rag/chat`。
2. 检查返回 `answer`、`citations`、`conversation_id`、`assistant_message_id`。
3. 调用 `/internal/rag/chat/stream`。
4. 检查 SSE 是否收到 `delta`、`citations`、`message_end`。
5. 查询 `retrieval_logs`。

通过标准：

- 非流式接口完整返回。
- 流式接口前端能逐段显示。
- 引用来源可打开。
- `retrieval_logs` 有对应记录。

### 6. 会话验收

验收步骤：

1. 创建会话。
2. 连续提问两轮。
3. 查询会话列表。
4. 查询会话消息。
5. 修改会话标题。
6. 删除会话。

通过标准：

- 消息按时间排序。
- 只能访问自己的会话。
- 删除后列表不再展示。

### 7. 反馈验收

验收步骤：

1. 对 assistant 消息提交反馈。
2. 查询会话消息时查看反馈状态。
3. 取消反馈。

通过标准：

- 反馈记录写入 `answer_feedbacks`。
- 会话列表可体现是否有未处理反馈。

### 8. 知识库和批量任务验收

验收步骤：

1. 调用 `/internal/rag/knowledge-bases`。
2. 确认返回 `items`、`default`、`total`，且包含 Java 共库 `knowledge_info` 或 RAG 文档中已有知识库。
3. 对多个附件调用 `/internal/rag/documents/batch/reparse` 或 `/internal/rag/documents/batch/rechunk`。
4. 使用返回的 `batch.batch_id` 调用 `/internal/rag/jobs?batch_id=...`。
5. 使用 `/internal/rag/jobs?attach_id=...` 查询单个附件的任务。
6. 调用 `/internal/rag/documents/batch/knowledge-base`，确认不存在的 `knowledge_id` 返回 400。

通过标准：

- 批量接口返回 `batch_id` 和每个附件的 `job_id`。
- `document_jobs.params` 中能看到 `batch_id`、`batch_index`、`batch_label`。
- 任务列表可按 `batch_id`、`attach_id`、`status` 过滤。
- 批量调整知识库会刷新知识库版本，后续检索缓存不会复用旧范围。

### 9. 性能优化回归验收

验收步骤：

1. 使用较大文档测试上传，确认超过 `MAX_UPLOAD_SIZE_MB` 时提前返回 413。
2. 对同一问题调用 internal chat，观察同一请求内 direct QA、向量召回、QA 召回不会重复计算 query embedding。
3. 在 Redis 可用时观察 embedding 缓存批量读写是否正常。
4. 使用不同 `access_scope` 提问，确认权限过滤后引用不会包含无权限文档。
5. 执行 0010 迁移后，确认新增索引存在。

通过标准：

- 上传大文件不会导致进程内存异常上涨。
- 问答接口无 500，引用文档满足权限范围。
- `idx_documents_visible_indexed_scope`、`idx_chunks_content_trgm` 等性能索引已创建。
