## 三、交付验收用例

### 1. 服务启动验收

验收步骤：

1. 准备 `.env`。
2. 启动 backend 和 worker。
3. 调用 `/`。
4. 调用 `/api/v1/health`。
5. 使用 Java JWT 调用 `/internal/rag/health`。

通过标准：

- 服务返回 200。
- internal health 返回 `{code:0}`。
- backend 和 worker 日志无启动异常。

### 2. Java 鉴权验收

验收步骤：

1. 使用正确 Sa-Token JWT 调用 internal health。
2. 使用错误密钥签发的 JWT 调用。
3. 使用过期 JWT 调用。
4. 不带 Authorization 调用。

通过标准：

- 正确 token 成功。
- 错误、过期、缺失 token 返回 401 或对应错误。

### 3. 文档入库验收

验收步骤：

1. 上传一个小型 txt 或 pdf 到 MinIO。
2. Java 调用 `/internal/rag/documents/process`。
3. 轮询 `/internal/rag/jobs/{job_id}`。
4. 查询 `/internal/rag/documents/{attach_id}`。
5. 检查数据库 `documents`、`document_parse_results`、`document_chunks`、`chunk_embeddings`。

通过标准：

- 任务状态最终为 `succeeded`。
- 文档状态为 `indexed`。
- 切片和向量数量大于 0。

### 4. 权限过滤验收

验收步骤：

1. 准备一篇 `publish_scope=dept` 的文档，发布部门为 A。
2. 使用部门 A 用户提问。
3. 使用部门 B 用户提问。
4. 使用 `admin_all` 用户提问。
5. 使用 `deny_attach_ids` 排除该文档后提问。

通过标准：

- 部门 A 可召回。
- 部门 B 不可召回。
- 管理员可召回。
- 显式 deny 后不可召回。

### 5. 问答验收

验收步骤：

1. 调用 `/internal/rag/chat`。
2. 检查返回 `answer`、`citations`、`conversation_id`、`assistant_message_id`。
3. 调用 `/internal/rag/chat/stream`。
4. 检查 SSE 是否收到 `delta`、`citations`、`message_end`。
5. 查询 `retrieval_logs`。

通过标准：

- 非流式接口完整返回。
- 流式接口前端能逐段显示。
- 引用来源可打开。
- `retrieval_logs` 有对应记录。

### 6. 会话验收

验收步骤：

1. 创建会话。
2. 连续提问两轮。
3. 查询会话列表。
4. 查询会话消息。
5. 修改会话标题。
6. 删除会话。

通过标准：

- 消息按时间排序。
- 只能访问自己的会话。
- 删除后列表不再展示。

### 7. 反馈验收

验收步骤：

1. 对 assistant 消息提交反馈。
2. 查询会话消息时查看反馈状态。
3. 取消反馈。

通过标准：

- 反馈记录写入 `answer_feedbacks`。
- 会话列表可体现是否有未处理反馈。

## 四、上线前检查清单

- `.env` 已按生产环境配置。
- `SA_TOKEN_JWT_SECRET` 与 Java 一致。
- PostgreSQL 扩展已安装。
- Alembic 或初始化 SQL 已执行。
- MinIO bucket 已创建并可读写。
- Redis 可连接。
- DeepSeek、Embedding、Rerank API Key 可用。
- backend 和 worker 均已启动。
- `/internal/rag/health` 通过。
- 文档入库到 `indexed` 通过。
- 普通问答和流式问答通过。
- 权限过滤用例通过。
- 数据库和 MinIO 备份策略已确认。
